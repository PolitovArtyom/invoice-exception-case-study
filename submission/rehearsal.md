# Проверка на чистом клоне

Клон лежал по пути с пробелом, запятой и двойной кавычкой. Приложение запустили через Docker Compose, карточки открыли в Firefox. Запросы на регистрацию и предложения взяли из записей и повторили через MCP реального приложения. Для самого чтения PDF есть [демонстрации в Claude Code](demos/).

## Запуск с пустым хранилищем

Команды из корня клона на Linux x86-64 с Docker Engine 29.1.2 и Compose v5.0.0:

```sh
docker compose up --build --wait
docker compose exec -T app curl -fsS http://127.0.0.1:8080/health
docker compose exec -T app curl -fsS http://127.0.0.1:8080/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

Проверка готовности вернула `{"status":"ok"}`. Список кейсов и карточка 001 открылись. У 001 результат `clear`. MCP вернул семь инструментов — `open_case`, `get_company_data`, `register_invoice`, `propose_match`, `assess_invoice`, `get_assessment` и `get_case_history`. В схеме параметры чтения и предложения имеют тип объекта JSON.

| История после перезапуска | Выполнить `docker compose restart app` и `docker compose up --wait`. Сравнить `get_case_history`, карточку и историю в API страницы до и после. | Пять ревизий 010, подтверждение и хеш PDF сохранились. В карточке по-прежнему видно, кто подтвердил предложение. |

| Повторная загрузка | Повторить тот же вызов `register_invoice` для 004. | Ревизия 3 получила `duplicate`. Оценка и принятие из ревизии 2 остались в силе. |
| Сохранение и сброс тома | Выполнить `docker compose down`, затем `docker compose up --wait`. Сравнить истории. После сброса тома 004 и 010 снова без чтения, 101 и 102 заблокированы по исходным данным. |

## Запуск официальной проверки

CI запускает официальный скрипт на экспорте `linux-x64`. Остальные экспорты и Docker-адаптер проверили один раз в этой репетиции и исключили из CI. [Все проверки CI](../README.md#для-разработчика)

- Собрали пять автономных вариантов по команде экспорта из README. Для `RID` использовали `linux-x64`, `linux-arm64`, `osx-arm64`, `osx-x64` и `win-x64`. Проверили исполняемый файл и библиотеку SQLite в каждом экспорте.
- Запустили `dist/linux-x64/InvoiceDesk.Adapter` с Python в контейнере. [Команды для экспорта Linux x64](../README.md#проверка-экспорта-linux-x64-в-docker)
- Запустили `./scripts/adapter-docker` с Python на хосте. [Команды для Docker-адаптера](../README.md#запуск-через-docker-вместо-экспорта)
